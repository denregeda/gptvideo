# 10. HTTPS/WSS и безопасный переход экранов

Сервер автоматически создаёт локальный удостоверяющий центр (CA) и
сертификат nginx. REST, медиадоставка и WebSocket новых агентов работают по
проверенному TLS; отключение проверки сертификата (`-k`, `verify=False`) в
агенте не используется.

## Автоматизация на сервере

`install_server.sh` перед запуском контейнеров вызывает:

```bash
bash tls/manage_tls.sh ensure
```

Скрипт идемпотентен:

- при первой установке создаёт долгоживущий локальный CA;
- выпускает серверный сертификат для `display.local`, `localhost`, `nginx`,
  IP хоста и значений `TLS_EXTRA_SANS`;
- обновляет серверный сертификат заранее, не меняя CA;
- проверяет цепочку, срок и набор SAN;
- никогда не меняет автоматически CA, срок которого заканчивается.

Ключи лежат в `tls/generated/`, имеют права `600` и исключены из git.
`ca.key` нужно хранить в защищённой резервной копии. Агентам передаётся только
публичный `ca.crt`.

Настройки `.env`:

```dotenv
TLS_SERVER_NAME=display.local
TLS_EXTRA_SANS=10.0.119.100,signage.example.lan
TLS_RENEW_DAYS=30
TLS_LEGACY_HTTP=true
```

После изменения имени/IP повторно запустите `bash install_server.sh`:
сертификат будет перевыпущен под тем же CA.

## Доверие браузера администратора

Один раз импортируйте `tls/generated/ca.crt` в хранилище доверенных корневых
сертификатов рабочего компьютера администратора. Импортируется именно
публичный `ca.crt`, не `ca.key` и не серверный ключ. Перед переносом можно
сверить отпечаток на сервере и рабочем месте:

```bash
openssl x509 -in ca.crt -noout -sha256 -fingerprint
```

После импорта браузер должен открыть адрес без предупреждения. Не закрепляйте
исключение безопасности вручную: предупреждение означает, что CA не установлен
либо адрес отсутствует в SAN сертификата.

## Комплект для Astra Linux 1.8

На сервере:

```bash
bash tls/export_agent_bundle.sh /tmp/agent_bundle
```

Каталог содержит `install.sh`, папку `agent/`, публичный `ca.crt` и
`SHA256SUMS`; приватных ключей в нём нет. Скопируйте каталог на мини-ПК и
запустите:

```bash
cd agent_bundle
sudo bash install.sh https://10.0.119.100 <ТОКЕН> <SCREEN_ID> toor
```

Установщик проверит CA, добавит его в хранилище Astra, запишет
`scheme=https`, `port=443`, `ca_file=/etc/ds-agent/ca.crt` и проверит
`/health` без отключения TLS. REST и WSS используют один корень доверия.

## Переход без остановки эфира

По умолчанию `TLS_LEGACY_HTTP=true`. В этом режиме:

- панель на HTTP получает перенаправление `308` на HTTPS;
- новые агенты работают по HTTPS/WSS;
- старым агентам временно доступны по HTTP только `/api/`, `/api/ws/`,
  `/media/` и `/health`.

Переводите экраны волнами: пилот 1–2 экрана, затем группы. После каждой волны
проверяйте онлайн-статус, WSS и воспроизведение. Когда все агенты используют
HTTPS:

```bash
sed -i 's/^TLS_LEGACY_HTTP=.*/TLS_LEGACY_HTTP=false/' .env
bash install_server.sh
```

Теперь весь порт 80 только перенаправляет на HTTPS.

## Постоянный контроль

```bash
bash tls/manage_tls.sh check
bash selfheal.sh --dry-run
bash smoke_test.sh
```

`selfheal.sh` проверяет TLS при каждом запуске, заранее обновляет серверный
сертификат под тем же CA и пересоздаёт nginx. Панельная самодиагностика
`GET /system/selfcheck` также проверяет цепочку, hostname и оставшийся срок.
