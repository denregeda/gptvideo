# 05. GitHub CI и выпуск изменений

Workflow `.github/workflows/ci.yml` автоматически проверяет каждый pull request
в `main`, каждый push в `main`, запускается вручную и ежедневно в 03:00 МСК
(00:00 UTC). Права встроенного `GITHUB_TOKEN` ограничены чтением содержимого.

## Контуры проверки

### Fast checks and pytest

- синтаксис всех отслеживаемых shell-, Python- и JavaScript-файлов;
- отсутствие `.env`, `tls/generated`, приватных ключей и key/pem-файлов в git;
- валидность `docker compose config`;
- TLS: идемпотентность, DNS/IP SAN, сохранение CA при перевыпуске,
  переходный и строгий HTTP-режим, отказ на некорректном имени;
- полный набор pytest с JUnit-отчётом.

### Docker HTTPS, WSS, smoke and UI

На чистом Ubuntu runner автоматически:

1. создаётся одноразовый `.env` без production-секретов;
2. выпускаются временные CA и TLS-сертификат;
3. собираются и запускаются все семь контейнеров;
4. применяются и проверяются миграции;
5. запускается smoke-тест, включая HTTPS и настоящий WSS handshake;
6. запускается браузерный UI/E2E-прогон;
7. стек и тестовые Docker volumes удаляются при любом результате.

Если интеграционный job падает, `ci/collect_ci_diag.sh` прикладывает artifact
`integration-diagnostics`: состояния контейнеров, безопасно очищенные логи и
TLS-диагностику. Срок хранения — 14 дней. Тестовые значения `.env` не
публикуются и не используются на реальном сервере.

## Локальное воспроизведение

Быстрый контур можно запустить в рабочем каталоге с существующим `.env`:

```bash
bash ci/fast_checks.sh
bash run_tests.sh
```

Полный контур предназначен для чистого runner и защищён одновременными
признаками `CI=true` и `GITHUB_ACTIONS=true`, чтобы случайно не пересоздать
production-окружение. Для работающего сервера его эквивалент:

```bash
bash smoke_test.sh
bash ui_test.sh
bash selfheal.sh --dry-run
```

## Правило выпуска

Изменение готово к объединению только когда оба job зелёные. Автоматического
развёртывания на Astra Linux нет намеренно: сервер обновляется контролируемо
по инструкции `08_ОБНОВЛЕНИЕ_СЕРВЕРА.md` после бэкапа.

Критерии остановки или отката:

- любой обязательный CI job красный;
- миграция не применилась;
- HTTPS/WSS, вход, основной цикл эфира или кабинет рекламодателя не прошли;
- после обновления контейнер нездоров или пилотный экран не вернулся онлайн.

При сбое сначала скачайте diagnostics artifact, исправьте причину и повторите
workflow. Не объединяйте изменение обходом красной проверки.
